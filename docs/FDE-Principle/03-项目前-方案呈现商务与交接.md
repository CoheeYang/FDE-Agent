# 03 项目前 Ⅲ：方案呈现、商务与交接

阶段目标：把诊断结论变成「多方案 + trade-offs」的专业呈现，商务条款匹配风险，并向下游（专家/交付团队）高质量交接。子阶段：方案呈现 → 分流建议 → 商务与合同 → 交接。

## 3.1 方案呈现：多方案 + trade-offs

- **原则（Palantir 口述原则）：给客户多个可行方案，并给出每个方案的 trade-offs，让客户基于约束做选择**——而不是替客户做一个「最优解」。`[口述·未核验原文；与 Palantir Ontology「决策支持而非决策替代」哲学一致，P14 已核验]`
  - 落地形式：方案对比表（能否覆盖问题 / 内部代价 / 主要风险 / 可撤回程度 / 前置条件五列），Bain FashionCo 的路径比较结构同源。`[外部·已核验：Bain D17，本项目转写]`
  - **对 Agent 的要求**：输出 R 路线时默认给替代路径与放弃条件，不给单一推荐——与「敢说不」互为表里。
- **原则：敢说「不」是 FDE 与外包的试金石**。真实案例：客户带预算要求投 Google Ads，调研后核心建议是「建议不投」，附渠道决策矩阵（全力做什么/延后什么/各附证据）——客户反而更信任。「放弃某个场景 ≠ 看衰客户」，写「放弃」必须同时给更好的替代。`[课程·2.2]`
- **原则：用能跑的 demo 代替一百页方案**。方案说服不了客户的三个原因：方案是抽象的（客户脑补的和你想的不是同一个东西）；表态无成本（「挺好的」毫无承诺）；方案里的 AI 永远聪明，demo 里的 AI 才会犯错——客户要亲眼看到它怎么表现、怎么出错，才能建立真实预期。`[课程·2.2]`
- demo 三纪律`[课程·3.4 + 2.5]`：
  - **宁可窄，不能断**：一张报表端到端跑通 > 十张各做两步（宽而断 = 到处是半成品）；
  - 场景、术语、操作路径必须是客户未来的真实语境（数据可合成）；
  - **demo 阶段主动暴露脏数据和长尾**——「现在暴露的成本是一点面子，上线后暴露的成本是信任甚至赔偿」。
- demo 的第一作用不是让客户说「哇塞」，而是让客户说**「不对」**——人对着能跑的东西才会说真话；每次演示必问：「要怎样，你才会点'同意'？」`[课程·4.1]`
- MVP + MVA 双重验证：MVP 回答「值不值得做」，MVA 回答「做不做得成」（真实数据下准确率下限/数据工具接得通/规模下延迟成本可接受三根承重柱）。`[课程·3.4]`

## 3.2 分流建议（FDE-Agent 的输出规范）

- **六条路线 + 一个状态**（完整定义见主研究文档 §9.2）：R0 学习自助 / R1 标准软件 / R2 流程数据权责先对齐 / R3 内部团队+短期专家 / R4 有范围的 FDE 发现验证 / R5 安全合规专家联合介入；`needs_evidence` = 暂定方向 + 最少补证动作，不许硬选。`[本项目设计]`
- **推荐 R4 必须能解释**：正在确认的业务问题及量级；为什么 R0/R1/R2/R3 不够；FDE 补哪项内部缺口；最小发现范围与停止条件；谁参与确认、还缺什么。**不做「超过 75 分就请专家」式的加权自动规则**——任意权重制造精确感并掩盖强制条件。`[主研究文档 §9.3]`
- 必要性/准备度/紧迫性三维度分开判断：数据不足可能正是需要短期发现的原因（「有必要，但先确认访问与口径」是合法结论）；完全没有业务目标且组织不愿给任何核验条件，才暂不进入技术实施。`[主研究文档 §9.1]`
- 经济判断纪律：可兑现净收益 = 已确认业务收益 − 外部费用 − 内部投入/集成/迁移/培训/维护；**不从「每月省 100 小时」直接推出「值得投 100 万」**；高影响风险事项不因 ROI 低而省掉专业处理。`[主研究文档 §9.4 + Bain D16 迁移]`

## 3.3 商务与合同

- **OLA（结果级协议）四要素**`[课程·2.4]`：交付什么结果；怎么衡量（北极星+基线+归因，精确到公式，用客户业务语言不用 FDE 黑话）；谁对衡量负责（落到具名负责人）；审核节奏（按指标变化周期）。
- 收费结构：基础费（覆盖探索期与最低投入，含 token 成本）+ 效果分成（增量部分）。应对「凭什么分你 10%」：只从增量产生、原盘不受损、无增长不收——谈完焦点自动转向「基线与归因怎么定」。`[课程·2.4]`
- **合同必须写客户配合义务**：谁给数据权限、谁推流程调整、谁按时决策反馈；客户未履行不全算供应商头上。`[课程·2.4]`
- 对赌的前提：「沉淀没做到位就去对赌，那不叫商业模式创新，那叫赌博。」供给侧三前提：外环沉淀（第二客户成本降到零头）、知识资产化、Agent 让陪跑可复制。`[课程·2.4]`
- **能在商务阶段拦住的私有化，是最便宜的私有化**；拦不住的，把源码交付/知识产权/使用权三件事分开写进合同。`[课程·4.2 + 行业篇]`
- 承诺边界（Baseten）：讲清取舍、给可信的时间估计、约定异常沟通机制——不接「永远不可能满足」的承诺换取签约。`[外部·已核验：Baseten P19]`

## 3.4 交接（给专家/下游团队的一页交接卡）

诊断完成不是终点，交接质量决定下游效率。交接卡模板（主研究文档 §14.1）：

```text
本次判断：暂定 R?；紧迫性；证据状态
业务问题 / 已确认事实与出处 / 目标与必须保留的约束
竞争解释与反证 / 已考虑的低成本替代
需要哪类专家补什么 / 最小发现范围
下一次会谈需要的角色与材料
技术选项核验截至（知识/运行版本）
新技术改变建议的条件 / 停止-继续-改变条件
用户已确认内容与未确认项
```

- **原则：人类专家能接着访谈，不需要从头问一遍**——这行字是交接质量的唯一标准。`[主研究文档 §14.1]`
- 引用绑定：交接卡每条结论至少指向五类证据之一（user_statement / provided_artifact / computed_result / external_reference / working_hypothesis）。`[主研究文档 §12.3]`
- **「资料只说'跨系统整合可能困难'时，不能写成'你们一定存在严重数据孤岛'」**——推断与事实的升级边界。`[主研究文档 §12.3]`
