# 06 踩坑手册：失败模式与行业红线速查（全程适用）

用法：先按 §1 识别症状（出了什么问题），再按 §2 追结构性原因（为什么总出这个问题）。预警看组合，不看单一信号。

## 1. 六大失败模式（症状 → 解法）

| 失败模式 | 症状 | 解法/预防 |
|---|---|---|
| **咨询陷阱** | 客户专属代码比通用代码长得快；实质是「借软件外壳的高端咨询」 | 像遵守交付期一样遵守平台提交纪律；拒绝沉淀不回平台的交付 |
| **每客户雪花化** | 新客户进来第一反应是「这家不一样，要单独做」（连续出现即开始雪花化） | 每次部署必须留下可复用模式，否则不算真正完成 |
| **英雄工程师** | 「这个客户只有老王能处理」——听着是表扬，实为严重风险信号 | 每客户至少两名工程师；关键认知写成文档；把「只有一个人懂」当风险管理 |
| **demo 债务螺旋** | demo 允诺的体验生产撑不住，团队反复填差距而非推进交付 | 靠过度承诺才能拿的单子一开始就放弃；主动暴露脏数据；不压缩硬化阶段 |
| **赞助人崩塌** | 力挺的高管离职/调岗/失势，新领导引入自己熟悉的供应商 | 至少两个赞助人；尽快建立自下而上的真实使用；救不回来就止损 |
| **倦怠死亡螺旋** | 从最资深的人率先离开开始：资深走→压力传导→离职加速 | 刻意轮换（同一客户连续两季无新学习产出即轮换）、强制休整、同伴互助、清晰成长通道 |

`[课程·6.1]`

**跨模式预警仪表盘（每季度看组合）**：专属代码持续增加；新客户部署周期持续缩短（反直觉项：与其他信号同现时，「快」可能只是复制定制或省略工程化补强）；资深工程师流失率上升；可支持项目的高管储备减少。`[课程·6.1]`

**警示案例（IBM Watson × MD 安德森）**：累计 6200 万美元、系统从未真正用于一位患者；推动项目的高管离开后崩塌，以审计报告收场——审计明确说不评价技术，只审采购、超支和治理：**项目先在组织层面出问题，技术还没接受检验。**`[课程·6.1 转述]`

## 2. 中国六大结构性坑（季度体检题）

1. **利润坎**：客单价和利润率养得起这支 FDE 团队吗？
2. **人才坎**：半年内有想留的工程师因「不想驻场」离开吗？真问题是驻场，还是驻场没带来成长？
3. **晋升坎**：有没有不离开专业一线也能成长的路径？
4. **抽象坎**：回看最近三个项目，沉淀了什么跨客户可复用的东西？
5. **组织坎**：现场 FDE 改一个方案要过几级审批？授权不足持续消耗客户信任。
6. **市场坎**：最近输的订单，是输给更好的方案，还是输给低价？

用法：每项红/黄/绿，至少两位一线 FDE 参加（一线感受比报表早暴露问题）；不求全绿——选最差的一道，下季度只做一个针对动作，下次先复查它。`[课程·6.2]`

## 3. 客户侧人性面（踩坑高发区）

- 中国 ToB 底层画像六特征（关系销售/定制开发/价格低廉/拖欠尾款/私有部署/现场服务）是风险错配下的理性自保；病根是「**标准的软件撞上不标准的流程**」。`[课程·7.1]`
- 「外来者说一百句，不如自己人说一句」——推广靠客户内部 champion。`[课程·7.2]`
- 「同样一个系统，警报发给谁，决定了它是救命工具还是背景噪音」（坦帕案例：发给床旁护士 95% 被忽略，发给专职响应团队才有效）——**采纳设计落到组织与工程，不指望用户自觉**。`[课程·7.2]`
- 单一赞助人风险、怀疑者转化（给他真实角色：第一个测试者，他挑的毛病认真修——专业和较真从阻力变质检）、政治是双向的（自己公司内部同样要画干系人地图）。`[课程·3.3/3.5]`
- 客户行为不会说谎：被绕着走、用一半切回 Excel 的功能就是最诚实的反馈；demo 上点头 ≠ 验收。`[课程·4.6]`
- 数据信任的不可逆性：**效果不好可以改，数据泄露无法撤回，一次事故清零且不可恢复。**`[课程·4.6]`

## 4. 行业红线速查（高影响判断）

| 行业 | 红线/注意 |
|---|---|
| 金融 | 本地部署/国产模型/代码控制常见；要求代码多是为供应商变更后的可持续运维——源码交付、知识产权、使用权分开写合同 |
| 政企 | 信创无讨价还价空间；模型/数据/平台/运行责任必须在甲方主导体系内；换模型不可怕，评估集和 Harness 扎实即可 |
| 医疗 | 最终决策权永远在人；文档生成再快，过不了审核价值为零 |
| 制造 | **确定性归规则，概率归模型**——概率模型输出必须过确定性闸门才能碰物理世界 |
| 能源 | **安全红线的判断权永远在人**；行业私有知识极深 |
| 零售/客服 | 托付三级跳铁律：每升一级护栏加一层审计；永远保留转人工（Klarna 回摆教训：情绪价值只能由真人提供）；强行拦截令人深恶痛绝 |

## 5. 与 Agent 产品相关的坑（本项目补充）

- **转介漂移**：分诊 Agent 系统性滑向「推荐贵的服务」——R4 推荐率必须做护栏指标（[方案B](../benchmarks/方案B-在线产品指标.md)），R0/R1 案例在评测集占比 ≥30%（[方案A](../benchmarks/方案A-能力基准-FDE-GAPS.md)）。`[本项目设计]`
- **伪纠错**：用户纠正后只改字段不重检判断；评测用纠错题专门覆盖。`[主研究文档 §13.2]`
- **静默补全**：把未知写成确定结论；`needs_evidence` 是合法且必须的输出。`[主研究文档 §13.4]`
- **知识时效衰减**：技术供给变化让旧方案失效或让定制变标准——T 维度与撤回机制（技术时效性研究全文）。`[本项目设计]`
- **评测自证**：让被测模型给自己打分、或让模拟受访者和被测系统共享知识实现——评测过于容易而不自知。`[GAPS A03 + 主研究文档 §13.2]`
