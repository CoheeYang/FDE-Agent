# 01 项目前 Ⅰ：获客与双向筛选

阶段目标：用「结果」吸引对的客户，筛掉不该接的项目。本篇 4 个子阶段：价值主张 → 战场选择 → 双向筛选 → 准入判断。

## 1.1 价值主张：客户为结果付费，不为工具付费

- **原则**：卖「把这件事整个替我做了」的结果，不卖平台/系统（听着就是成本）。`[课程]`
- 预算层级事实：营销预算 > BPO 人力外包 > IT 采购（数量级递减）——客户用预算把供应商从「卖产品」推向「卖结果」。`[课程]`
- 中国 ToB 三宗罪（价值难衡量、责任无法界定、风险全在客户）是甲方在风险错配下的**理性自保**，不是恶意；方案若主动解决风险共担（基线+归因+OLA），就是低价竞争中的差异化。`[课程]`
- RaaS 参考：约定基线 1000 万 → 承诺 1200 万 → 增量收 10%；无增长不收分成，客户原有盘不受损。`[课程]`

## 1.2 战场选择：选对再承诺

- **原则（a16z 四条件）**：问题足够关键（重大损失级，非后台提效 10%）、客户足够集中、客户间有共同模式、场景有数据/集成/监管门槛。`[课程]`
- 客单价-模式匹配：几十万 → 轻FDE（标准产品+行业模板，远程）；几百万 → 中FDE（关键场景驻场+基础费分成）；数千万 → 重FDE（全周期嵌入+对赌）。**最贵的错配：用咨询公司的成本结构，赚软件公司的钱。**`[课程]`
- 强监管行业（金融/政企/医疗）是 FDE 主场：他们买的不只是合规，是**控制权**（模型和数据在哪运行、代码谁掌握、决策谁作、出了事能否追溯）。`[课程]`

## 1.3 治理即产品（强监管入场券）

- **原则**：把治理能力做成可单列报价的产品能力，不与功能开发抢预算。`[课程]`
- 三笔账：预算账（治理投入单列）、采购账（合规部门是治理的直接使用者，早参与评审就成为内部盟友——「业务部门买功能，合规部门买'出了事说得清'」）、规模账（一个客户的审计要求沉淀成配置模板复用）。`[课程]`

## 1.4 双向筛选八问（进场前必须全过）

**立项四问（筛项目）**`[课程]`：
1. 有没有一个真正说了算的负责人？
2. 有没有真实预算？
3. 用什么指标衡量成功？
4. **有没有明确的退出条件？**——「一个没有退出条件的项目，不是项目，而是一份无底洞式的支持合同。」

**客户四问（筛组织）**`[课程]`：
1. 有没有一位有分量、愿意带你进业务会议的引路人？
2. 真实数据和权限给不给（哪怕只读开始）？——给不给权限最能看出客户愿不愿为合作改变自己。
3. 反馈周期多长？——建议发出去一个月不知对错，迭代优势归零。
4. 谁为探索买单？——合同能否容忍头几周「只是把业务学明白了」的不确定期。

> 任一问明确否定，不硬进场。**「外包的客户不用改变自己，FDE 的客户必须改变自己。」**`[课程]`

**外部印证**：何时一般实施支持就够、不需要 FDE——先检查问题是否常见且规则清楚（对应分诊 R1）、内部是否已有推进能力（R3）。`[外部·已核验：First Round P23]`

## 1.5 需求受理的纪律（FDE-Agent 产品的直接场景）

- **原则**：客户最初说出的「想上 AI / 想请 FDE」是**他自己想出来的解决方案**，只能信一半；第一步不是接单，是把诉求还原成业务问题（哪个角色、哪个情境、哪项决策出了什么具体影响）。`[课程·3.1节总原则 + 外部·已核验：微软 D12 问题定义模板]`
- 焦虑型诉求（「同行都 AI 化了」）先处理焦虑的事实基础，不顺着焦虑给方案。`[内部问题卡 Q004，docs/research/访谈问题卡手册.md]`
- 已经带着具体工具/方案来的客户：先问方案背后要解决什么、试过什么，再评估——「别拿着锤子找钉子」。`[课程]`
