# 05 项目后：交接、沉淀与复利

阶段目标：客户接得住、公司沉淀得下、判断真假 FDE。子阶段：运营交接 → 结项沉淀 → 复盘 → 止损退出。

## 5.1 交接：自治三级阶梯

FDE 主导运行、客户跟着学 → 客户负责日常运营与一线问题、FDE 后方支持 → 客户独立运行、持续改进、FDE 只管平台层。`[课程·5.1]`

- **毕业标准不只看系统上线**：值班、告警、知识维护、评估集责任是否真正转移给客户。标杆：Palantir×坦帕综合医院第四阶段，新应用由医院内部团队和医师科学家自己设计部署。**「FDE 真正的交付物还包括一个有能力的客户团队——系统会过时，被带出来的客户团队才是复购和口碑的来源。」**`[课程·5.1]`

## 5.2 结项沉淀清单（不完成不算正式结项）

一页纸三件事：①学到什么；②哪些经验已形成**平台提交**（四要素：现象/根因/建议形态/受益面）；③哪些内容明确不值得沉淀、为什么。`[课程·5.2]`

- 单客户→产品节奏（按月/季度）：已现重复需求（pipeline 里至少还有一个客户提过）→ 优先通用化；单一客户适用 → 保持原样不强行抽象；中间态 → 先做模板。**锚点只有一句：「有没有第二个客户会走这条路。」**`[课程·5.2]`
- 沉淀三层次：代码（通用开关）→ 模式（同类客户模板）→ 抽象（行业语义模型，等第二个样本出现再做；抽象的单位是业务语义不是代码）。`[课程·5.2]`
- 沉淀仪表盘：第二客户时间（第二次比第一次快多少）；单位经济（第二次成本是否降到零头——**加人买得来速度，买不来毛利**）；平台提交率。危险信号：**客户专属代码比通用代码长得快 = 正在滑向咨询陷阱。**`[课程·5.2]`

## 5.3 私有知识转化（AI 时代 ToB 的护城河）

- **边界三问**（决定知识归你还是归客户）：给同行业下一家看，原客户会觉得泄密吗？能回溯到具体企业的数字/名称/组织细节吗？描述的是行业怎么运行还是这家企业怎么运行？三问全过才进共享行业层。「私有知识的'私有'，是相对同行，不是相对客户。」`[课程·5.2]`
- 四步转化：抽取（沉淀清单+复盘+结构化访谈；**最高效通道是产品交互记录——用户对建议的同意/拒绝/争论，「客户的不信任恰恰是 Agent 最昂贵的训练数据」**；关键是及时，aha moment 过三个月就想不起来）→ 脱敏（只抹名字不抹数字=没脱敏，懂行的人一眼猜出是哪家）→ 结构化（Context/Skill/Workflow 三形态）→ 入库（版本管理、评估集覆盖、持续迭代——**知识库没人负责更新，上线那天就是质量巅峰**）。`[课程·5.2]`
- 个人习惯：每个项目结束写**三条脱敏后的行业规律**，两年积累就是和别人的最大差别。`[课程·5.2]`
- 护城河再定义：「存量代码是包袱；需求理解、行业 know-how、客户信任才是资产。」警惕把「客户离不开」当护城河——被绑定而离不开，与因持续创造价值而被选择，是两回事（永久拐杖是反模式）。`[课程·5.2]`

## 5.4 五步复盘框架

目标（业务语言还是技术语言？）→ 实际结果（数字与差距）→ 差距归因（**归到环节不归到个人**，主持人控制时长防甩锅会）→ 可复用资产（**分水岭**：目标全达成但零资产只算勉强及格；逐条列并写归属人）→ 下一步打哪一仗。`[课程·5.3]`

- 复盘会三要点：让**销售**参与（当初的目标只有销售记得最全、离客户最近）；产出就是一页纪要（一页写不下=还没复盘清楚）；既不开成庆功会也不开成批斗会。`[课程·5.3]`
- **跑通的标准：业务结果、可复用资产、下一步，三者同时成立。**`[课程]`

## 5.5 止损与退出

- 项目级止损三条件（同时满足即启动退出评估）：①失去核心赞助人三个月内无新支持者；②真实使用量持续下降且找不到原因；③可复用资产已基本提炼出来——**有些项目商业上失败、资产上是赚的**，沉淀做完跟客户体面分手，这单就没白做。`[课程·5.4]`
- **退出评估不让项目负责人自己主持**（沉没成本绑架决定），换交付线之外的人牵头。「进场前谈好的退出条件，还得有人在翻车的时候真的敢启用。」`[课程·5.4]`
