# FDE-Agent 基准与指标体系（docs/benchmarks/）

研究日期：2026-10-03。本目录回答两个问题，给出三个互补方案：

1. **能力基准**（离线）：怎么知道 Agent「会问、会诊、会分流」，而不是只会说？——见 [方案A](方案A-能力基准-FDE-GAPS.md)。
2. **产品指标**（在线）：ToB 分诊 Agent 用户低频使用、不能拿 DAU 衡量，上线后如何客观比较不同版本表现？——见 [方案B](方案B-在线产品指标.md) 与 [方案C](方案C-版本对比与实验框架.md)。

## 三个方案一句话

| 方案 | 回答的问题 | 何时用 | 成本 |
|---|---|---|---|
| A：FDE-GAPS-T 能力基准 | 这一版 Agent 的专业能力达标了吗 | 每次发布前必须全量跑（回归门禁） | 高（建题+评审），跑起来低 |
| B：在线产品指标 | 线上真实用户用得怎么样 | 上线后持续采集，周报/月报 | 中（埋点+专家抽检） |
| C：版本对比与实验框架 | v2 真的比 v1 好吗，好多少 | 每次发版决策时 | 中（影子+灰度流程） |

三者关系：**A 是门禁（能不能上），B 是体温计（上去之后怎么样），C 是天平（两版之间怎么选）**。A 的题库来自 B 的真实错误回流；C 的裁决依据 = A 的回归分 + B 的在线分 + 专家抽检。

## 与既有研究的关系

- 本目录是 [主研究文档第 13 章](../FDE-Agent-企业AI转型分诊与访谈研究.md)（评测维度）与 [技术时效性研究第 6 章](../research/技术时效性与重大变化监测研究.md)（T 维度）的**工程落地方案**，维度定义以那两份为准，此处不重复推导、只做引用与补充操作化细节。
- GAPS 的四维定义（Grounding/Adequacy/Perturbation/Safety）来自蚂蚁健康×北大人民医院的公开论文（arXiv:2510.13734，2025-12 发布，已读 v2 摘要与量子位报道全文）。**T（Timeliness）是本项目新增维度，不是官方 GAPS 标准**——这是相对阿福类医疗产品的差异化所在：医疗指南半年一换，技术供给每月一变。
- 在线指标的设计参照了可核验的业界先例（均已在方案内标注来源与核验状态）：GitHub Copilot 的 acceptance rate / 激活率口径（GitHub 官方文档）、客服 AI 的 containment rate 口径、Google HEART 框架（Rodden et al., CHI 2010）的任务化改写。

## 快速选择指南

- 你要发新版 → 先跑方案A门槛 → 按方案C灰度 → 用方案B看板盯两周。
- 你要向客户/投资人证明产品有效 → 方案B的 L3/L4 层（结果与采纳）+ 方案A的专家一致率。
- 你只有一周人力 → 先做方案A的最小题库（30 题）+ 方案B的埋点清单，方案C可以后补。
