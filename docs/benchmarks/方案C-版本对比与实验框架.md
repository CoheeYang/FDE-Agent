# 方案C：版本对比与实验框架（低频 ToB 场景的 A/B 与灰度）

状态：设计稿。回答「上线时知道不同版本表现如何」的操作问题。前提：方案A（离线门禁）与方案B（在线埋点）已就位——本方案是两者的联动机。

## 1. 为什么经典 A/B 在这里不可行，用什么替代

- **流量小**：早期企业客户数量级可能是 10–50 家、周会话 10² 级；经典 A/B 检验（检测 +5% 相对提升）需要的样本量在此不可得。
- **异质性强**：行业×角色×风险等级的方差大于版本间方差，随机分流会被混合偏差淹没。
- **低频**：一个用户可能整月只来一次，「同期对照」周期长到失去决策价值。

替代组合（业界对低频高价值 ToB 的通行做法，非统计新发明）：

```
离线回归（方案A全量题库）        ← 检测能力退步（灵敏，可控）
      ↓ 门禁通过
影子评测（shadow，同题双跑）      ← 检测行为变化（无风险）
      ↓ 差异可解释
灰度按企业切换（非随机分流）      ← 真实环境验证（风险受控）
      ↓ 两周观察窗
版本归因会议（离线+在线+专家）    ← 决策保留/回退/迭代
```

## 2. 四步流程

### Step 1 离线回归门禁（发布前，强制）

- 新版（知识/harness/模型任一变化）跑方案A全量题库。
- 门槛表见方案A §6；**任何一项不过即阻断**，无「先上了再说」。
- 记录五元组快照（知识, harness, 模型, 工具, 评测集版本）——没有快照的版本禁止上线（继承技术时效性研究 §5.5，这是版本归因的地基）。

### Step 2 影子评测（发布前 1–2 天）

- 用最近 N（≥50）条**真实线上会话回放**：旧版已有人类确认的答案作参照，新版并行作答。
- 对比四件事：分流方向改变率、新增引用来源分布、S4 规则命中变化、平均轮数/成本变化。
- **分流方向改变 >15% 且无法逐例归因 → 暂缓发布**（既可能是真提升，也可能是回归）。
- 隐私：回放数据不出环境；符合客户授权范围。

### Step 3 按企业灰度（发布中）

- 切换单位是**企业**（不是会话、不是用户），先切 1–2 家低风险试点企业。
- 观察窗 14 天（覆盖至少一个复访周期），看方案B五层仪表盘，重点：
  - L3 用户纠正率、专家复核一致率（每周 20 例抽检不中断）；
  - L2 放弃点分布是否迁移；
  - L5 S4 与撤回时延。
- **回退触发条件（预先写死）**：纠正率上升 >50%、专家一致率跌破 80%（对标阿福 90% 口径留缓冲）、任何 S4 漏网、L1 会话量异常下跌 >30% 且无外部解释。

### Step 4 版本归因会议（观察窗结束）

输出一页纸：

| 维度 | 证据 | 结论 |
|---|---|---|
| 离线分 | 方案A 五维 + 分层 diff | 升/平/降，降在哪层 |
| 在线分 | 方案B L1–L5 两周对比 | 哪些指标显著移动 |
| 混合偏差核对 | 期间企业构成、行业分布、知识快照事件 | 变化是版本还是构成 |
| 专家抽检 | 分歧案例逐条 | 可命名的原因 |
| 决策 | 保留 / 扩量 / 回退 / 转问题回流入库 | 责任人与日期 |

## 3. 小样本下的判断纪律

- **用「一致性区间」不用点估计**：20 例专家抽检一致率报「14/20（70%，95% CI 46–88%）」，CI 用 Wilson 区间；CI 过宽即承认不可判定，增加下周样本而非硬下结论。
- **分层固定效应**：版本对比永远在「同行业×同角色」层内做，层内样本不足就合并周次滚动窗口（4 周滚动）。
- **预先登记**：发版前写下预期改善的指标和方向；发版后只看预期指标 + 护栏指标（方案B反指标），防止事后挑显著（p-hacking 的组织学预防）。
- **序贯规则**：灰度期每 7 天一次中期检查，但只对「回退触发条件」生效（安全侧提前停止）；有效性判断只等观察窗结束——不对称设计防止「看到好数字就停」。

## 4. 版本谱系与可回退性

- 每个线上版本 = 五元组快照 + 方案A得分卡 + 灰度报告，三者归档不可篡改（git tag 即可）。
- 任何在产会话开始的版本固定到会话结束（继承技术时效性研究 §5.5：一场访谈不中途换条件）。
- 回退演练：每季度随机指定一次「假回退」演练（切回上一个快照跑影子），验证回退路径真实可用——对应 SOP 原则「预案没演练过，约等于没有」。

## 5. 与数据飞轮的闭环

```
线上五类错误信号（用户纠正 / 专家推翻 / S4 拦截 / 放弃热力 / T 撤回）
  → 每月归因分类（知识缺失 / 检索失败 / 推理错误 / 格式问题 / 流程设计）
  → 对应修法（补知识 / 改检索 / 改 prompt / 改状态机）
  → 新增回归题（题库棘轮增长）
  → 下一版走 Step 1–4
```

回流率（每月新增回归题数 ÷ 线上错误信号数）本身作为工程健康指标，目标 ≥ 30%。
