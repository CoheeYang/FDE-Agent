# 方案B：在线产品指标体系（ToB 分诊 Agent 仪表盘）

状态：设计稿。解决「用户有问题才来、低频 episodic 使用，DAU 类指标失真」的问题。

## 0. 为什么互联网指标失真，以及用什么替代

分诊 Agent 的使用模式：客户在**决策时刻**（要不要上 AI / 要不要请 FDE / 选哪条路）进来做 1–3 次深度访谈，可能隔几周复访。因此：

- DAU/WAU 失真（一个人一周来一次可能是健康信号——他把问题想清楚了才回来）。
- 时长失真（聊得久可能是低效，也可能是深度）。
- **正确的度量单位是「会话级任务结果」和「建议级采纳行为」**，不是「人·天」。

业界可核验的同类先例（ToB 低频工具均走向任务/采纳口径）：

| 先例 | 口径 | 来源与核验状态 |
|---|---|---|
| GitHub Copilot | acceptance rate（建议采纳率）、license 激活率、assigned license 活跃占比；官方判断「早期 5–10% 活跃属实验信号，健康早期采用为 60–80%」 | docs.github.com 官方文档，已核验摘要（2025） |
| 客服 AI | containment rate（无需人工即关闭的会话比例）、转人工后解决率 | cekura.ai 等（2026-09），行业通用口径 |
| 蚂蚁阿福「医生把关」 | AI 与三甲医生一致率 >90%，15% 用户选择把关 | 中国日报/经济参考报（2026-06），已核验报道 |
| LLM 运维层 | task success rate、tool-call error rate、groundedness proxy、safety violation rate、cost per successful task | Agent Reliability Engineer 角色蓝图等行业材料（2026），通用实践 |

## 1. 北极星候选（选一个，其余做护栏）

**北极星：单位周期内「完成合格分诊的会话数」**——合格 = 产出了带完整证据链的分流结论（含 `needs_evidence`）或交接卡，且未被用户/专家在后续推翻核心判断。

为什么不是「好评率」：好评测的是体验礼貌，分诊产品最贵的失败（漏转介）用户当场根本发现不了。北极星必须绑定「结果正确性代理」，把专家复核一致率（§2 L3）作为它的质量校正项。

替代候选（若商业模式侧重转化）：「带合格交接卡进入专家通道的会话数」。**护栏**：R4 推荐率不得随版本上升而系统性升高（防销售化漂移，见方案A §5）。

## 2. 五层指标仪表盘

### L1 规模与触达（流量是否健康）

| 指标 | 定义 | 备注 |
|---|---|---|
| 周分诊会话数 | 独立访谈会话（≥3 轮算有效） | 按新老访客分 |
| 覆盖企业数 / 活跃企业占比 | 授权企业中本周有会话的 | 对齐 Copilot「激活企业」口径 |
| 复访率 | 7/30 天内再次会话的会话占比 | 低频产品的留存代理 |
| 入口转化 | 打开→≥3 轮深度会话比例 | 识别开场流失 |

### L2 过程质量（访谈是否专业、是否负担）

| 指标 | 定义 | 健康信号 |
|---|---|---|
| 有效问题密度 | 改变/约束了后续判断的问题 ÷ 总提问数 | 越高越好；低 = 问卷化 |
| 重复提问率 | 与既有信息重复的问题占比 | ≤5% |
| 澄清率 | 因歧义主动澄清的轮占比 | 有但不过度 |
| 用户「不知道」后的降级处理率 | 用户答不知道时改问可答问题的比例 | 100% 目标（中性可答性） |
| 会话放弃点分布 | 按轮次的放弃热力 | 定位负担过重的子阶段 |
| 端到端时延与每会话成本 | P50/P95；token 成本 | 运营约束 |

### L3 结果质量（分诊是否正确——产品的命根）

| 指标 | 定义 | 备注 |
|---|---|---|
| 分流明确率 | 会话结束时给出 R0–R5 或 needs_evidence 的比例 | 悬而不决是失败 |
| `needs_evidence` 使用率与命中 | 使用占比；后续补证后方向不变的比例 | 防两个极端：从不承认未知 / 万事皆未知 |
| 用户纠正率 | 用户纠正 Agent 事实/口径的会话占比 | 高 = 抽取不稳；每次纠正必须触发判断重检（可日志验证） |
| 核心判断存续率 | 交接卡核心结论在 30 天内未被用户/专家推翻的比例 | 北极星的质量核 |
| **专家复核一致率** | 抽样会话，独立专家对分流方向的认同比例 | 对标阿福「医生把关」90% 口径；每周固定样本（如 20 例），分层抽样 |
| 引用可回查率 | 结论引用能定位到 user_statement/artifact/computed/external/hypothesis 五类来源的比例 | 100% 目标（主研究文档 §12.3） |

### L4 采纳与价值（用户用脚投票）

| 指标 | 定义 |
|---|---|
| 报告/交接卡导出率 | 完成会话中导出 Markdown 的比例 |
| 行动项执行回访率 | 交接卡「补证动作」在复访中被引用/执行的比例（复诊时核对） |
| 复诊转化 | 30 天复访中带新材料（报表/口径确认）的比例 |
| 用户明示反馈 | 会话尾 CSAT 单题（1–5）+ 自愿文字；只做趋势，不做 KPI |
| R0/R1 自助闭环率 | 被分到自助/标准软件路线的用户，复访时确认「已自行解决」的比例——**分诊产品独有的价值证明** |

### L5 安全与时效（红线与新鲜度）

| 指标 | 定义 |
|---|---|
| S4 线上拦截数与漏网数 | 规则拦截记录 + 用户/专家举报核实 |
| 过时建议率 | 依赖已失效技术事实的会话（由时效雷达 flagged 的复诊比例） |
| 撤回时延 | 确认旧能力失效→限制相关推荐的耗时（P50/P95） |
| 知识版本滞后 | 当前线上知识快照落后最新已核验能力卡的天数 |

## 3. HEART 映射（向管理层汇报时的通用语言）

Google HEART（Rodden et al., CHI 2010，长青框架）：

| HEART | 本产品对应 |
|---|---|
| Happiness | L4 CSAT 趋势 + 专家一致率 |
| Engagement | L1 复访率、L4 导出率（深度行为，非时长） |
| Adoption | 活跃企业占比、入口转化 |
| Retention | 30 天复访率、覆盖企业留存 |
| Task success | L3 分流明确率 × 判断存续率（北极星拆解） |

## 4. 埋点最小清单（v1 实现范围）

会话开始/结束、每轮（角色、是否澄清、是否重复）、纠错事件（字段、旧值、新值、是否触发重检）、分流输出（路线、置信、needs_evidence）、引用绑定（五类来源计数）、导出、S4 拦截、知识快照版本。**所有事件带五元组版本戳**（继承技术时效性研究 §5.5），否则版本归因不可能。

## 5. 反指标（刻意不采）

- 对话轮数 KPI 化（会诱导凑轮或砍轮）。
- 时长/字数（深度≠长度）。
- 好评率作为核心 KPI（见 §1）。
- R4 推荐率与营收挂钩（销售漂移的制度性根源）。
